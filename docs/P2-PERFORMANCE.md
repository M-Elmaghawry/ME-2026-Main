# صيانة الأداء — P2

## القياسات

القياسات التالية من بناء محلي للإنتاج، قبل P2 وبعدها، وباستخدام gzip الافتراضي في Node.js. الأحجام عشرية، وليست قياسًا لزمن التحميل الفعلي.

| المقياس | قبل P2 | بعد P2 تقريبًا |
|---|---:|---:|
| ملف بدء JavaScript الخام | 860.6 كيلوبايت | 226.7 كيلوبايت |
| JavaScript لبدء التطبيق بعد gzip | 259.7 كيلوبايت | 75.2 كيلوبايت |
| الصفحة الرئيسية كاملة مع JavaScript المشترك وSEO، بعد gzip | 259.7 كيلوبايت | 182.5 كيلوبايت |
| مجموع 110 صور أصلية | 43.63 ميغابايت | محفوظة كأصول |
| مجموع أكبر نسخة WebP بديلة لكل صورة | — | 8.09 ميغابايت |
| جميع نسخ WebP بمختلف الأحجام | — | 13.48 ميغابايت |

انخفض JavaScript المطلوب للصفحة الرئيسية وSEO بنحو 30% بعد الضغط. أكبر نسخ الصور البديلة أقل من الأصول بنحو 81% إجمالًا. هذه مجموعات للمقارنة؛ لا تُحمّل الصور كلها في زيارة واحدة، وقد يختار المتصفح نسخًا أصغر حسب عرض الصورة وكثافة الشاشة.

تحتوي نسخة النشر على الصور الأصلية والبدائل لتبقى الروابط القديمة ومعرض الرسومات بالحجم الأصلي متاحين. لذلك يزيد حجم ملفات النشر، بينما تقل بيانات الصور المستخدمة في العرض العادي. لم يُقَس Core Web Vitals أو الأداء على اتصال حقيقي.

## تحميل الصفحات

- جميع الصفحات الاثنتي عشرة تستخدم `React.lazy` و`Suspense`؛ لا تتضمن حزمة البداية تنفيذ الصفحات.
- بيانات SEO في المتصفح تُحمّل بشكل منفصل، مع الحفاظ على بيانات HTML المولّدة قبل JavaScript.
- يظهر مؤشر انتظار مترجم أثناء تحميل الصفحة، ورسالة مع إعادة المحاولة إذا فشل تحميلها.
- أُزيل مزوّد React Query ومكوّنا الإشعارات ومزوّد التلميحات من جذر التطبيق لأنها لم تعد مستخدمة في تدفقاته الفعلية. مكونات واجهة المستخدم الجاهزة الباقية داخل `components/ui` متاحة للاستخدام اللاحق وتخضع لإزالة الشيفرة غير المستخدمة في البناء.

## الصور المتجاوبة

المصدر هو `public/`، والمعالجة في `scripts/optimize-images.mjs` باستخدام sharp كاعتماد تطوير. لا تُشحن sharp إلى المتصفح.

تُولّد صور WebP فوتوغرافية حتى 1920 بكسل، وصور شعارات حتى 640 بكسل مع ضغط دون فقد. تؤخذ اتجاهات EXIF في الاعتبار، وتُحفظ شفافية الشعارات. تُشتق أسماء المخرجات من محتوى المصدر وإعدادات التوليد. يعاد استخدام الملفات الموجودة، وتُحذف فقط المخرجات القديمة التي أنشأها المولّد نفسه.

```tsx
<ResponsiveImage
  src="/projects/01-Shigri-Neom.jpg"
  alt="وصف واضح للصورة"
  sizes="(min-width: 1024px) 360px, 100vw"
/>
```

يعرض `<picture>` مصدر WebP مع `srcSet` وأصلًا احتياطيًا للمتصفحات الأخرى، وتبقى فئات التصميم على الصورة. التحميل الكسول وفك الترميز غير المتزامن هما الافتراضيان. استخدم `priority` فقط لصورة مهمة ظاهرة أولًا؛ فيجعلها المكوّن eager وبأولوية مرتفعة. مكوّن `MotionImage` يوفّر السلوك نفسه للصور المتحركة.

عند إضافة صورة أو استبدالها:

1. ضع الأصل داخل المجلد المناسب في `public/`.
2. شغّل `npm run images`.
3. أضف الأصل وتحديث `src/data/imageManifest.json` إلى Git. لا تضف `public/optimized/`؛ يُعاد توليده آليًا عند تشغيل Vite أو البناء.
4. حدّث مرجع البيانات، ثم شغّل `npm run check`.

عند تغيير خوارزمية التحويل أو خيارات الضغط، حدّث `VERSION` في المولّد لإبطال الملفات المخزنة سابقًا.

## البيانات والاعتماديات

- شعارات العملاء موجودة في `src/data/clients.ts`، وتستخدم صفحة الخدمة مجموعة مختارة منها.
- رقم واتساب الأساسي ورابطه ورسائل التسجيل وبيانات التواصل تأتي من `src/config/site.ts`.
- بيانات الدورات والخدمات والمشروعات مستقلة عن صفحات العرض.
- أُزيل `@tanstack/react-query` و`lovable-tagger` بعد التأكد من عدم وجود استخدام فعلي لهما.
- أُضيف sharp إلى اعتمادات التطوير، مع ملف قفل يشمل الحزم الأصلية الاختيارية لـ Windows وLinux.
- عدّاد الدورات لا يبدأ مؤقتًا عند غياب عرض، ويتوقف بعد انتهائه.

## اختبارات منع التراجع

`npm run check` يشغّل lint وفحص الأنواع وكل الاختبارات والبناء. يشغّل GitHub Actions مجموعات الاختبارات نفسها قبل النشر.

- `test:p1`: أولوية اللغة، المدخلات والتخزين، الأسعار والعروض، بيانات التواصل والعملاء، وSEO.
- `test:images`: فك ترميز الصور الناتجة، المقاسات والشفافية، عدم تعديل الأصول، إعادة استخدام المخرجات، وصحة HTML وأولوية تحميل الصور في الجذر ومسار المستودع.
- `test:routing`: التوجيه المباشر وSEO في مساري النشر، وتقسيم الصفحات وحدود حجم JavaScript.

الحدود الحالية: أقل من 120 ألف بايت gzip لبدء التطبيق، وأقل من 210 آلاف بايت gzip للرئيسية مع SEO، وأقل من 500 ألف بايت خام لأي قطعة JavaScript منفردة. إذا فشل أحدها، راجع السبب قبل رفع الحد.

لا تغني هذه الاختبارات عن فحص متصفح فعلي، واختبار الرسائل وCAPTCHA على النطاق المسموح، والتحقق من إعداد GitHub Pages بعد النشر.
